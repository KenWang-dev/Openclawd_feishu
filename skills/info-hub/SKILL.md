# info-hub — 信息枢纽与周报维护

## 目标

把 Ken 从"每周人工整理周报"中解放出来：AI 读取全部信源 → 加工 → 维护企微在线周报（PPT/Excel，老板可见），Ken 只做最后确认和据此跟进。

## 信源清单与角色

| 信源 | 频率 | 性质 | 角色 |
|------|------|------|------|
| 项目文档（用户资料、访谈记录、PRD、Demo） | 低频更新 | 完整、权威 | **项目基线**：进度/方案/需求的事实依据 |
| 会议记录（开头一次 + 中间若干次确认） | 定期、密度大 | 决议集中 | **增量决议源**：提取结论、变更、待办、风险 |
| 企微群消息 / 私聊 | 不定时、碎片化 | 补充与确认 | **变化侦测源**：只提取异常与确认信息，不作结论依据 |

## 信息加工规则

### 提取原则（充分且必要）
- 项目文档 → 对齐基线：PRD 范围、当前进度、关键决策历史
- 会议记录 → 每次提取：① 结论/决议 ② 需求或方案变更 ③ 新增待办（含负责人、期限）④ 风险与争议点
- 群消息/私聊 → 只提取：@Ken、阻塞、延期、新需求、关键确认；其余丢弃

### 冲突裁决：时间维度优先
- **最新且一致 > 过去**：同类信息以时间最新的为准，旧信息被覆盖时在周报中标注变更（如"原定 X → 现改为 Y，来源：11/15 会议"）
- **无法判定时**：不强行裁决，给出 AI 建议 + 依据 + 备选，**标注"待拍板"**，由 Ken 决定
- 所有写入周报的结论必须带溯源（来源：哪次会议/哪条消息/哪份文档 + 时间）

## 周报维护模式（增量，不重写）

1. **稳定骨架**：周报结构固定（项目概览 / 本周进展 / 关键决议与变更 / 风险与待拍板 / 下周计划），模板变动只改骨架不改历史内容
2. **增量更新**：每次只更新有变化的板块/单元格，新增内容标注"本周新增/变更"
3. **老板视角**：向上汇报口径——结论先行、进展可量化、风险带应对，避免流水账
4. **待拍板区**：无法判定的信息集中在此区，附 AI 建议，Ken 确认后转入正式板块

## 工作流

1. **采集**：通过各接口读取三类信源的增量内容
2. **加工**：按提取规则结构化，标注时间与来源
3. **裁决**：时间优先合并；无法判定进待拍板区
4. **更新周报**：维护企微在线 PPT/Excel，增量写入
5. **通知 Ken**：推送变更摘要（改了什么、哪些待拍板），Ken 确认收尾

## 平台说明

- 执行平台为 **Dora**（连接各信源接口）；本 skill 定义加工规则与工作流规范，接口对接在 Dora 侧实现
- 周报载体：企微在线 PPT / Excel

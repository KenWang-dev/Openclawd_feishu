# 金句银行（quote-bank）

Ken 用真实场景和代价验证过的决策原则。每条金句是一笔资产：入库有质检（挑战），流通有记录（验证×N），越用越值钱。

## 何时使用

| 场景 | 触发信号 | 动作 |
|------|---------|------|
| 录入 | "存金句" / "这句入库" / "金句银行" | 走三段式录入流程 |
| 召回 | 用户在讨论：做不做/选哪个/要不要止损/值不值得/复盘对错/引用原则 | 走召回流程 |

## 录入工作流（三段式）

```
用户口述（散乱没关系，不打断）
   → ① 记录：忠实记下 原话+场景+理由+使用场景，不加工不改写
   → ② 挑战：提 2~3 个考验，用户回应或坚持；用户说"跳过挑战"则放行
   → ③ 提炼：按模板生成卡片，用户过目确认 → 写入 references/ 并更新总账
```

**挑战环节规则**（质检工序，不是审讯）：
- 固定问 2~3 个，从这三个角度选：反例（有没有见过不成立的情况）、幸存者偏差（成功是运气还是规律）、适用边界（推到什么极端会失灵）
- 用户回应后立即停止追问，不打消耗战
- 挑战与回应记入卡片"挑战记录"区——这是金句的质检报告

**入库动作**：
1. 按下方卡片模板新建文件，命名 `QB-{下一编号}-{中文核心词}.md`（核心词 4~8 字，简洁直观）
2. frontmatter：id / quote / tags（2~4 个自由标签，延迟分类）/ status: 验证×1 / created（精确到分钟 `YYYY-MM-DD HH:mm`——同日多笔按时间排序）
3. "原话"区保真引用用户原始表述，一字不改
4. 在 `references/_ledger.md` 总账追加一行

**卡片模板**：

```markdown
---
id: QB-{编号}
quote: {金句核心词}
tags: [{标签1}, {标签2}]
status: 验证×1
created: {YYYY-MM-DD HH:mm}
---

## 原话

> {Ken 的原始表述，保真，一字不改}

## 场景（为什么验证了它）

{当时发生了什么，代价是什么}

## 理由（为什么成立）

{逻辑链条}

## 使用场景（何时调用）

{后续什么情况下该想起它}

## 失效边界（何时不适用）

{什么情况下这条会失灵；初始可为空，随使用补充}

## 挑战记录（入库考验）

- 挑战：{反例/幸存者偏差/边界之问} → 回应：{用户的回应或坚持}

## 验证记录

- {YYYY-MM-DD HH:mm} 入库，验证×1
```

## 召回工作流

1. 读 `references/_ledger.md` **总账**（不要读金库全量）
2. 按用户当前讨论的场景匹配金句（tags + 摘要 + 使用场景），命中 1~3 条为宜，宁缺毋滥
3. 只读命中卡片的完整内容，然后主动引用：
   - **正向**："你自己验证过：「{quote}」——当时场景是{场景}。现在这件事落在它的使用场景内，建议按原则走。"
   - **反向**："注意，这个情况触碰了「{quote}」的失效边界：{边界}。此时别用这条。"
4. 用户的新讨论若再次应验某条金句，提醒："这条又应验了，要不要把验证计数 +1？"确认后更新卡片 status 和总账

**召回纪律**：引用必须忠实于卡片原文，不演绎不拔高；没有命中就不引用，不硬凑。

## 维护规则

- **延迟分类**：满 30 条后，从 tags 实际分布归纳分类轴（MECE），重组总账分组，卡片内容零改动
- **与 memory.md 分工**：本银行只存"带场景验证的决策原则"（重格式、大颗粒）；协作偏好、工作规则归 memory.md（轻格式、小颗粒）。拿不准时问用户
- **边界即资产**：用户报告某条原则失灵时，不删卡片，改写"失效边界"并降低 status——失败的边界和成功的原则一样值钱

## 总账

金句索引存于 [`references/_ledger.md`](references/_ledger.md)：录入后追加行，召回时先读它。本文件只定义工作流，不存数据，永不膨胀。

# Research Sources Mapper - 研究领域信息源图谱构建器

> 版本：2026040601
> 像"画地图"一样——先看清全域，再标注核心地标，最后给出最优路线。

**专治**："我想研究 XX 领域，但不知道从哪找信息"、"信息太多不知道看哪个"。

---

## 核心方法论

### 第一性原理
研究任何新领域，本质需求只有三件事：
1. **知道别人做了什么**（现状认知）→ 论文/综述
2. **知道别人怎么做出来的**（方法复现）→ 开源项目/代码
3. **知道前沿在哪、我能做什么**（创新突破）→ 社区动态/会议/数据

### MECE 七维度框架
所有信息源按以下 7 个维度归类，**相互独立、完全穷尽**：

| # | 维度 | 本质 | 价值占比 |
|---|------|------|---------|
| ① | 核心综述 | 已固化的理论知识 | ~40% |
| ② | 标杆项目 | 已验证的实现方法 | ~25% |
| ③ | 核心数据集 | 可复现的实验资源 | ~15% |
| ④ | 社区动态 | 未固化的前沿信息 | ~10% |
| ⑤ | 产业资源 | 商业化落地情况 | ~5% |
| ⑥ | 工具平台 | 提效的开发/仿真环境 | ~3% |
| ⑦ | 政策合规 | 边界与约束条件 | ~2% |

### 帕累托法则
- 前 3 个维度（综述+项目+数据集）贡献约 80% 研究价值
- 每个维度内，⭐ 标注的核心资源贡献约 60-70% 价值
- **核心原则：先吃透 20%，再扩展 80%**

### 交叉验证原则
- **每个维度至少 3 个信息源**，避免单一来源偏差
- 3 个来源形成三角交叉：类型 A（国际）× 类型 B（国内）× 类型 C（AI 工具）
- 同一主题在 3 个平台分别搜索 → 比对覆盖度 → 发现遗漏

## 输入方式

用户描述要研究的领域/方向，例如：
- "我想研究具身智能"
- "帮我找大模型微调方向的信息源"
- "量子计算这个领域，帮我画一下信息源地图"
- "我要做 Agent 开发框架的竞品分析，信息源有哪些"

## 工作流程

### Step 1: 领域理解与维度适配
- 分析用户描述的研究领域，判断领域特征：
  - **强学术型**（如量子计算）→ 维度①③权重更高
  - **强工程型**（如具身智能/自动驾驶）→ 维度②⑤⑥权重更高
  - **强政策型**（如数据安全/生物伦理）→ 维度⑦权重显著上升
  - **强社区型**（如 Web3/开源框架）→ 维度④权重上升
- 根据领域特征调整 7 个维度的价值占比和搜索重点

### Step 2: 七维度信息源搜索（每维度 ≥ 3 个）

**执行搜索策略（每个维度）：**

#### ① 核心综述（论文/知识库）
- 搜索 arXiv/Google Scholar 综述论文（关键词：`[领域] survey` / `[领域] review`）
- 搜索国内平台（CNKI/知乎专栏/腾讯新闻）
- 用 Semantic Scholar API 做引用图谱分析
- **产出**：3-5 篇必读综述 + 搜索平台链接

#### ② 标杆开源项目
- 搜索 GitHub（`awesome-[领域]` / `[领域] framework` / `[领域] benchmark`）
- 用 GitHub Topics 和 Stars 排序筛选头部项目
- 找 2-3 个代表性 demo/教程仓库
- **产出**：3-5 个标杆项目 + GitHub 链接

#### ③ 核心数据集/基准
- Papers With Code / Hugging Face Datasets / 领域专属数据集网站
- Google Scholar 搜索 `[领域] dataset` / `[领域] benchmark`
- 国内数据集（如适用）：智谱/百度/阿里等开源
- **产出**：3 个核心数据集 + 下载链接

#### ④ 社区动态
- 关键研究者/公司的 Twitter/X 账号
- 顶级会议（列出该领域 3-4 个核心会议）
- Discord/Slack/Reddit 社区
- Hugging Face Daily Papers / AI HOT 等聚合
- **产出**：会议列表 + 社区链接 + 关键账号

#### ⑤ 产业资源
- 头部公司及其 API/SDK 文档
- 行业报告（McKinsey/Gartner/IDC）
- 开发者文档平台
- **产出**：3-5 个产业资源 + 官方链接

#### ⑥ 工具平台
- 仿真/开发/测试环境
- IDE 插件/CLI 工具
- 云平台（AWS/GCP/Azure 的领域专属服务）
- **产出**：2-3 个核心工具 + 文档链接

#### ⑦ 政策合规
- 国际标准（ISO/IEEE）
- 出口管制/数据合规
- 行业法规（如适用）
- **产出**：按需列出，标注"初期可跳过"

### Step 3: 优先级标注
- 每个⭐标注附**一句话原因**：为什么它是核心
- 标注分三级：⭐⭐⭐（必须精读）→ ⭐⭐（推荐深入）→ ⭐（了解即可）
- 每个维度给出交叉验证策略说明

### Step 4: 输出格式化
- 生成 Markdown 文档（结构见下方）
- 可选：调用 pdf-styles skill 生成 PDF
- 可选：调用 processon-diagram-generator 生成研究链路图

## 维度适配指南（按领域类型调整）

### 强学术型（量子计算/理论物理/纯数学）
- ① 权重 → 50%，增加 Google Scholar、DBLP、MathSciNet
- ③ 数据集权重降低
- ⑤⑥ 产业/工具权重降低

### 强工程型（具身智能/自动驾驶/机器人）
- ②⑤⑥ 权重上升（项目/产业/工具是核心）
- ⑦ 政策权重显著上升（安全标准/法规）
- 必须包含仿真平台

### 强政策型（AI 安全/数据隐私/生物伦理）
- ⑦ 权重 → 20%+
- 增加政府官网、监管机构文件
- 增加法律数据库

### 强社区型（Web3/DeFi/开源框架）
- ④ 权重 → 20%+
- 增加 GitHub Trending / HackerNews / ProductHunt
- 增加 Discord 社区列表

### 强产业型（SaaS/企业软件/芯片设计）
- ⑤ 权重 → 15%+
- 增加上市公司财报、行业研报（IDC/Gartner）
- 增加 patent 数据库（Google Patents）

## 与其他 Skill 的关系

| Skill | 关系 |
|-------|------|
| `hv-analysis` | 本 Skill 提供"信息源地图"，hv-analysis 用地图中的信息源做深度研究 |
| `pdf-styles` | 本 Skill 产出 Markdown → pdf-styles 生成 PDF |
| `processon-diagram-generator` | 本 Skill 产出流程描述 → 可选生成可视化图表 |
| `skill-reader` | 无直接关系 |

**典型工作流：**
```
research-sources-mapper（画信息源地图）
    ↓
hv-analysis（用地图中的信息源做横纵深度研究）
    ↓
pdf-styles（输出研究报告 PDF）
```
